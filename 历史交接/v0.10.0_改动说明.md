# v0.10.0 基础工作能力

## 本次变更

在 v0.9.6 上扩展已有 `ybf_work_core` 与 `ybf_work`，复用任务序号、有限重试、总时限、打断、原跟随／等待恢复与现有补状态。没有整体移植参考模组或改写聊天界面。

- 感知：`ybf_work_resources` 使用朋友附近的实体与真实组件，识别地面物品、树苗／草、普通可砍树、已知能掉所需矿物的矿石。默认12世界单位，同时限定任务起点范围，移动不会逐次扩大搜索区域。
- 采集：支持 twigs、cutgrass、log、rocks、flint、goldnugget；优先拿已有地面目标物品，再选择对应植物／树／矿石。只捡所需资源，附带掉落留在地面，不为了凑数量丢弃多拿资源。
- 数量规则变更：原 v0.9.6 的“只算任务新增拾取”改为当前用户要求的“已有库存计入资源目标”。混合地面拾取也沿用总持有数量规则。整叠拾取仍可能超过目标，不人为丢弃。
- 工具：读取手持和背包／装备背包中的工具组件、限制与耐久，装备可用工具。CHOP/MINE 通过原版 BufferedAction，传入 invobject，由原版 OnUsedAsItem 扣耐久，未手动伪造工作结果。损坏后重查；缺工具时可按实际材料制作基础工具，无材料依赖递归。
- 制作：允许 axe、pickaxe、cutstone、boards、rope、torch。通过游戏 `GetValidRecipe`、builder 配方／科技／材料接口与原版 BUILD 执行。检查朋友自身科技和解锁、实际材料来源、产出空间；拒绝免费／预付材料模式、外部箱子材料。不会为探测容量临时生成样品。读取实际材料消耗和产出，结果不吻合则停止，不重复造物。
- 交付：原版 GIVETOPLAYER 每次1份，执行瞬间重查接收条件、容量和实际收发库存，累计到指定数量停止。无关物品、工具和剩余库存保留；拒收或满包不默认落地。可以部分交付后因接收条件变化停止，并报告已交付数量。
- 连续动作：不在 chopping/mining 的工作动画中再次发起工作或补给。每步检查条件→选目标→交给原版导航／动作→核对实际变化→更新进度→继续／结束。模型只给任务类型、资源、数量；不逐次决定走路和挥动。
- 落物等待：完成树木／矿石动作后留出最多3秒检查延迟落物，此期间只选已实际出现的目标掉落，不立即转去砍下一棵树。砍倒／敲碎本身不计为已入包。
- 防迟到：动作 validfn 与实际自定义执行器核对任务和尝试身份；取消／替换先失效旧尝试，清除缓冲与可中断工作动画。旧动作即使被状态图再次持有也不能继续执行。
- 失败：每目标最多2次失败／约8秒单次动作，工作总时限默认60秒，工具自动重建最多8次。不存在目标／资源不足／不满足制作条件／满包／拒收都保留具体结束原因。原等待任务成功或失败后返回原点尝试最多8秒，失败就在当前位置等待，不擅自跟随。
- 补状态：仍用既有需求迟滞和真实效果选择，在动作间隙执行；期间保留任务、数量和起点，下一步重新检查目标、工具和材料。总任务时限仍包含暂停时间。

## 供后续规划系统调用

`friend.components.ybf_work:Request(kind, prefab, quantity, player)`：kind 为 pickup/collect/craft/give；返回 accepted, reason, task_id。资源目标数量1至100；pickup 可不指定数量。give 要绑定持有小花的当前玩家。

`Status(task_id)` 返回 running 或 finished，以及真实数量／结束原因；仅保留最近结果，不能作为长期任务数据库。`Cancel(true)` 取消并恢复原模式；显式改跟随／等待使用现有命令路径。`Start` 仍兼容旧单类／最多3类混合地面拾取接口。

独立模块：`ybf_work_inventory`（真实持有计数）、`ybf_work_resources`（局部识别）、`ybf_work_crafting`（配方条件与真实消耗）。将来规划器可以调用这些检查与工作接口，本版没有多层材料规划。

## 验证证据与边界

已通过开发侧 Lua 模拟、原版 BufferedAction／工具耐久／选定动作函数参考测试和10项 Python 模型解析／后台传递测试；具体结果在 tests/v0100_lua_results.txt 与 tests/v0100_ai_results.txt。

Linux runner 使用 Lua5.4 解析，不能替代 DST 的 Lua5.1 与真实导航／状态图／网络验收。世界、导航与 builder 部分由测试替身模拟，真实制作动画、当前客户端版本与 DeepSeek 实际语言识别仍需玩家验证。两份参考模组仅作为源码学习材料；选定原版动作来自游戏源码镜像，来源见 tests/reference/reference_sources.md。

不要求重测已通过且未改动的聊天界面、游戏内密钥保存、多朋友菜单、洞穴等待全链路。窗口／密钥文件未改变。后台要升级并重启以加载新指令规则。

未知自定义矿物掉落函数不作为可产矿证据；非列出的特殊植物／树、战斗取材、取箱子、建科技站、跨洞穴找资源与完整材料规划暂不支持。无自动避险保证。掉落在工作边界外不会追出去；远处不活跃实体仍不保证持续模拟。制作容量检查保守，不依赖“消耗材料后会空出格子”的假设。
