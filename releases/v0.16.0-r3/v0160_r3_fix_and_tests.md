# v0.16.0-r3 点位传输确认与任务协议修复

## 对用户日志的核查

所提供server_log第1369行（00:03:18）和1376行（00:03:59）均为task4 await_location，随后task7取消；没有此任务的预制/施工记录，也没有对应点位处理反馈。task8明确parse_error recipient_conflict，没有下发工作。更早task1两次unobtainable_material是另一个材料阻碍。client_log与上述窗口没有对应点位Lua异常。未执行日志里其他模组打印的任何代码；原日志及个人信息不放入公开包。

这些证据支持“尚未完成位置接收”，不能定位到原RPC的哪项参数或哪个权限分支。旧接收器有多处静默return，客户端又在调用发送前删除虚影，且没有服务器回执；因此发送失败或拒绝都表现成虚影消失/朋友不动。这是本轮确认并修复的错误处理设计，不冒称已经证明原生网络编解码的某个具体字段就是现场根因。旧的寻路/返回状态解释不能单独解释这份日志。

## 修复内容

点位RPC改为一个有长度上限的JSON字符串；服务器仍验证朋友、持花权限、任务、目标、nonce、坐标、分片和朝向。每次处理记录received、accepted/rejected及原因；异常捕获反馈，不静默吞掉正常格式请求。位置提交成功才恢复原任务；单纯发送不能算位置已记录。

客户端选中后冻结虚影等待build_point_ack。发送失败、拒绝或5秒无回执都显示明确说明；超时可重试，没有自动重试/重新执行命令。只对匹配朋友/任务/目标/nonce的回执生效，成功后才删除虚影。服务器短期保存一笔回执，完全相同的重发不会再次提交；同nonce换坐标不覆盖已接受位置。正常鼠标输入在等待期间继续被拦截，避免旧代码关闭点选后同一次输入落入正常动作。

右键/Esc始终能退出客户端点选，即使网络故障；退出本地与服务器已取消是两件事。如果位置已经提交或网络无法确认，提示使用“取消任务”停止整个工作。整个任务取消继续走本地紧急指令；暂停/取消事件能清理等待回执的虚影，多目标取消事件按目标匹配，不能清掉另一个目标的点选。

recipient_conflict来自两个重复字段互相矛盾。协议现在以deliver布尔为唯一兼容交付标记，recipient由本地派生；非法接收者仍拒绝。目标、数量、mode、destination、原料限制均不因派生而改变，玩家当前原句仍校验目的地。纯建筑不走入包交付；混合任务仍由各自目标去向处理。提示词要求不再生成recipient；不通过多轮模型重试修复这个冗余字段。

模组、后台及游戏状态快照版本均显示0.16.0-r3，避免旧快照常量让实际版本难以辨认。r2默认点选/玩家坐标/地皮对齐规则继续保留。

## 验证结果与限制

现行Python76项通过，包括冗余接收者派生测试及原约束检查。14条自然请求经正式HTTP响应解码与游戏聊天入口；模拟模型故意输出deliver=false/recipient=player，仍进入正确建筑目标。

新增正式modmain注册的RPC接收器测试，传入单JSON包并调用真实Control.Submit，核实坐标/朝向/工作恢复/回执；另测坏参数、权限拒绝、相同nonce重发。客户端测试覆盖发出后保持虚影、丢包超时、拒绝、发送异常、旧回执、重复点击、不依赖网络的取消退出。Lua语法、基础任务回归及既有建筑逻辑模拟通过。详细日志tests/v0160_r3_*.log。

这些测试仍是Lua实体/网络替身，未运行DST原生TheNet传输、真实状态图或寻路。旧建筑模拟仍会直接移动朋友到动作点，仅能验证库存/预制/产物核验，不能计作真实走到点位的验证。没有真实模型调用或实际游戏验证，不声称本轮已在游戏中打通施工。

## 安装与一次最小实测

客户端、服务器模组和external后台必须一起替换为r3，保留api_key.txt，重启后台并重新进存档；本轮点位协议改变，不能混用旧客户端。先用取消任务清掉旧目标。

给朋友或友谊箱足够材料，然后说“在这里建一个科学机器”，点选一处合法空地：
1. 应先保留虚影等待服务器回执；接受后显示位置已确认并收起虚影。
2. 让开施工点，观察取材、预制、行走、放置。没有材料时应报告材料阻碍。
3. 如仍失败，不重复发送继续：观察是否出现发送失败/回执超时/服务器拒绝；server_log查[YBF POINT] received/accepted/rejected和[YBF BUILD] buffered/verified，client_log查[YBF POINT CLIENT] sending/accepted/rejected/ack_timeout。此链能区分没发出、没到服务器、接收被拒绝和接受后施工失败。

再做一次取消任务与普通物品任务回归即可。只有实际出现建筑实体才算游戏验收完成；回执只证明点位提交成功。
