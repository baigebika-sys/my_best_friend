# v0.16.0-r2 点选自动施工与玩家坐标定位修复

## 原因与改动

本轮源码审计确认：等待点选走通用BlockGoal，会提示“补齐条件后继续”并恢复原先模式/返回锚点；提交点选只清除blocked，没有清除returning或重新启用工作移动策略。这使选点后可能受到旧返回流程干扰。现在等待点选只提示点击操作；提交位置一次即恢复工作移动、使旧动作失效、清理返回状态，并自动继续。暂停中修改仍保留暂停，不擅自恢复。后台截图不能替代服务端异常栈，此处报告源码缺口与模拟复现，不声称所有实际停滞均同一原因。

过去本地Parse没有“在我这/脚下”；模型定位缺省也可误选free。现在当前原句在本地校验定位：无位置描述默认fixed；明确附近/找空地才free；明确玩家站位用player；明确地皮中心才tile。建筑命令中的造/建造/搭建纳入请求语法，不改名称索引或放松黄金/烧灼等限定词核验。知识询问不启动工作。

玩家坐标是服务器收到指令时记录的位置和分片，不能随玩家后来移动，也不会吸附成地皮中心。多座建筑只提供一个玩家/地皮点仍要求分别点选或改自由选址，不推导布局。朝向继续Q/E或既有数字朝向。

## 当前操作

- “造1个科学机器”“建造科学机器”：自动显示原版建筑虚影，左键选一次位置，随后朋友准备材料并施工，不用再确认或发送继续。
- “在附近建一个科学机器”：有限自由选址。
- “在我这建一个科学机器”“在我脚下造一个科学机器”：记录发起请求时玩家准确坐标，提示“位置已确认，请离开施工点”，玩家让开后自动施工，不需要点选。
- “按脚下地皮中心建”：仍使用单格/公共边/四格交点对齐，含义没有改变。
- 右键或Esc取消点选；取消任务/停止任务等紧急口令继续本地执行。

玩家占位等待是新增的明确规则：原版普通CanDeployRecipeAtPoint的实体过滤通常忽略player，不能依赖它来提示让开。固定位置和玩家/地皮点在准备阶段按真实配方min_spacing（至少0.5）检查本分片玩家；朋友本人不算阻碍。让开后自动继续，每次实际放置前再检查。持续占位超过90秒暂停并保留坐标、库存与预制；让开后“继续任务”重检。等待不会移动位置、推开玩家或无限阻塞其他可执行目标。原版地形/建筑占地仍另行核验，非法位置不偏移。

## 安装与最少验收

同步替换客户端、服务器模组和external后台，保留api_key.txt；重启后台并重新进入存档，不能只热替换已缓存Lua。若仍有旧任务先发送“取消任务”。

1. 只说“造1个科学机器”。选一个合法位置，之后不说任何确认或继续。检查朋友自动取材、靠近与施工；玩家移动不能改变位置。
2. 在空地说“在我脚下建一个木牌”。检查离开提示，留在原地时不得施工；走出占地范围后应自动建在原坐标，而不是地皮中心或朋友位置。
3. 说“在我这附近建一个晾肉架”，应自由选址；再用明确地皮中心指令确认对齐仍生效。
4. 点选已有建筑重叠处，必须说明位置非法且可以取消；等待玩家让开时也能暂停/取消。站定超过90秒检查有限等待，再让开并继续。
5. 普通采集、非建筑制作、友谊容器取材和知识查询各做一次必要回归。
