# v0.16.0-r1 固定点选修复与验收

基于v0.16.0完整包；不改变材料、仓库、非建筑制作与三种定位规则。

## 根因

服务器普通require模块ybf_build_control访问GLOBAL。官方756039 strict.lua禁止读取未声明全局；GLOBAL只在mods.lua生成的modmain沙箱存在。这会在发送点选通知时抛错；CancelPicks又复用同一路径，让取消在结束任务前中断。旧模拟没有严格全局约束。截图显示与这一链路一致，但后台截图没有服务端Lua异常栈，不能据此证明所有现场故障均同因。

上一版客户端只有点选钩子和提交后的网格标记，没有实际建筑虚影。这是实现缺口。

## 修复

普通模块使用真实_G发送通知，不再读取沙箱GLOBAL。通知失败记录开发日志，不能中断取消；取消任务增加独立保护，允许在uncertain状态直接结束。支持本地紧急口令：取消任务、取消工作、取消、停止任务、停止工作、停止、别做了；不依赖模型返回。

服务器点选事件携带已核验配方名。客户端生成该配方原版placer，使用原版鼠标跟随、地形与占地预览；Q/E按45度调整朝向。它不挂到玩家playercontroller.placer，不调用玩家制作接口。点击使用当帧虚影坐标，服务器重新核验，不以绿色虚影代替合法性检查。成功提交、右键、Esc、服务器取消和过期都会清理虚影与点选状态；预览加载失败退出点选并通知服务器取消。预制材料保留规则不变。

## 安装与脱困

同步替换客户端、服务器的my_best_friend模组和external后台，保留自己的api_key.txt；重启后台并重新进入存档，让客户端钩子与模块缓存更新。原版已预制建筑由builder存档保留，不能为解除任务而清空预制数据。进入后若仍有旧任务，发送“取消任务”。不要只热替换正在运行的Lua文件。

## 最少游戏验收

1. 拿着友谊小花与朋友对话：“在指定位置建一个科学机器”。聊天界面退出后，应出现跟随鼠标的科学机器虚影。先试右键或Esc取消，再说“改为指定位置”重开点选。
2. 选定空地；玩家立即走开。朋友应在记录位置施工，不跟随玩家移动。另选已有建筑重叠的位置，应报告非法而不偏移；取消任务仍有效。
3. 再选一种未用于专项适配的普通建筑，检查虚影外形、Q/E方向、实际材料消耗和建筑实体。
4. 在等待点选、材料准备、施工受阻三种状态发送“取消任务”。应结束工作；随后普通物品任务与附近自由建造正常。

## 验证边界

现行Python75项通过。本地Lua语法与既有聊天/UI回归、建筑模拟、自然语言HTTP入口回归通过；新增严格GLOBAL读取失败复现、原版配方placer创建/清理契约模拟、异常状态取消与通知故障不阻断取消测试。自然语言入口使用模拟提供商响应，客户端实体/输入/联网亦模拟。未进行真实模型调用或DST实测，虚影渲染及联机RPC仍需以上验收。
