# v0.14.0-r1 改动与最少游戏测试

## 审查结果与改动

原 ybf_knowledge.lua 的 Mentions 对整句做子串匹配，只取全句最长名称；Resolve 主要核验模型返回的普通名称/ID。二者组合可能吞掉限定词，也会漏掉多对象。现在按名称在句中的位置保留各处片段，只在重叠片段内取长名称；完整名称前后的未解释部分仍保留为待核实限定。标点中的限定也不静默丢弃。

本地核对模型选择与原句候选的一致性；模型提出存在的 prefab 也不能绕过原句。重名、错字建议、限定词未知、版本未核实分别反馈。查询保留多个对象；工作解析遗漏目标时会询问。吃、装备、修改对象也做原句核对。砍树的旧通用请求保留，点名特殊树/状态不擅自改成处理其他普通树。

动态显示名记录到实际对象实例，皮肤和同 prefab 状态通过独立绑定表达；它们不变成新的 prefab。没有核实变体执行条件时，不按普通对象下发工作。静态记录还可表达独立 prefab 的关系。识别规则没有添加“灼烧园艺锄”的专用事实或执行分支。

新增知识库数据层、离线官方脚本导入、可追溯适配数据、覆盖审计与按需细节分片。身份索引与详细属性/机制分开；本地查询只读。每条静态事实保存数字构建版本、出处/哈希/行号或核实网页与实现交叉证据、确定程度。候选脚本摘录不用于肯定回答。相同语义的事实冲突优先当前脚本，脚本本身冲突则作为缺口。

身份、属性、用途、配方、获取方式、机制、差异分别查询。用途问题不附整段配方或执行器名单；查询不改变现有任务。带明确对象的事实问题误走聊天时也会使用只读知识回答，避免直接采用模型背诵。底层数据不依角色扮演清除。

## 当前限制（必须了解）

这次交付完成名称保护和知识架构修订，尚未完成“覆盖当前官方内容的完整百科”。未提供当前游戏构建、完整脚本与中文文件，包内官方静态目录为明确的待导入状态。已加载游戏名称和真实对象数据继续可读；全面官方总数及其覆盖百分比目前未知。详情见 `知识覆盖报告_v0.14.0-r1.md`。

本地的特殊锄、新增对象、状态、皮肤和百科机制测试是合成样例；不证明真实“灼烧园艺锄”的机制、不证明当前官方新内容已覆盖。真实模型未运行，DST 游戏未运行。

保守名称检查可能对未收录的口语限定词多问一次；玩家补充完整名称后再解析。目标是避免错误操作。已经开始的工作、暂停/取消、补状态后恢复与真实入包/指定数量交付流程沿用原实现。

## 最少游戏验收

1. 名称保护：询问“园艺锄有什么用”“灼烧园艺锄有什么用”“园艺锄（灼烧）有什么用”。若当前游戏未提供后两种完整名称/状态依据，必须询问或说明未核实，不得当普通园艺锄回答或启动采集。存在实际特殊对象时，提供原句、完整显示名与来源资料再验证它的真实身份/状态关系。
2. 多对象和错字：“花瓣和斧头有什么用”“园艺锄和斧头有什么区别”“斧孑有什么用”。两种对象均保留；不确定错字询问，不启动动作。对一个确实同名的模组对象做一次消歧，可作为兼容性检查，不计官方覆盖。
3. 只读代表：朋友实际持有一份浆果和斧头，附近实际可见科学机器及一个生物；分别问属性、用途、设施身份、已见生物的机制。回答要区分真实字段与缺失机制，不凭模型补全。再问“石砖怎么制作”，应读取实际配方，其他用途查询不要无关地列整段配方。
4. 非普通配方对象：从你当前构建选择一个实际官方掉落/交易/转换对象，询问怎么获得和用途。导入当前数据并核验适配后才能验收可靠解释；当前无来源事实时必须说明缺口。认识名字不能算此项通过。
5. 新旧混合：选择当前构建新加入的一个对象和较早的一个对象，分别/同时查询。此项等待提供当前文件后补测；合成“测试新增物”不是官方验收样本。
6. 最少采集回归：无现成花瓣时“帮我采集2个花瓣给我”，应找到普通花、正常 PICK、真实入包、交付 2 个。再对成熟浆果或普通树枝做一次指定数量任务，确认仍共用普通流程。
7. 查询与取消：在采集途中问“石砖怎么制作”，原任务和进度保持；随后“取消这个任务”，已排队旧动作不得继续，已取得物品保留。暂停、继续或补状态恢复可按原基线步骤抽查，不需把所有旧测试重做。
