# v0.14.0-r1 开发说明、知识来源与版本

## 模块与接口

- ybf_knowledge_names.lua：UTF-8 名称片段、局部重叠选择、前后限定保留、英文大小写与词边界、同长度替换错字候选、通用树请求核验。不执行 Lua 源文件。口语理解主要仍由模型承担，保守判断可要求确认。
- ybf_knowledge.lua：Catalog / Names / Expressions / Mentions / Resolve。Resolve(..., true) 在工作入口核验原始表达，状态/皮肤/动态显示名未支持时不下发普通目标。Entry 结合实际对象原始字段和真实配方，Retrieve 按 facet 读取相关静态事实；AnswerMany 保留多对象，QuestionKind/QuestionName 只作模型聊天路由的事实保护。
- ybf_knowledge_store.lua：Identity 仅身份索引，Entry 按需加载详细分片，Facts 只返回构建一致的 verified 事实并处理语义冲突。模型表达或未来角色披露层不修改 data。
- ybf_official_knowledge.lua：本包明确待导入。当前没有完整官方输入，manifest.build=nil。不能用模组版本填入游戏构建号。
- Coverage：返回当前实例 runtime_registered/runtime_named 和静态统计；显式 runtime_is_not_official_universe=true。不会扫描全地图或提供未感知位置。
- Capability / CanAcquire 与原工作系统共用能力检查；静态来源不会自动添加执行许可，配方读取不会改变六个基线制作白名单。

## 静态数据复现

完整游戏来源由用户同一安装收集（见 `需要提供的游戏文件.md`）。使用 Python 标准库，不 eval/exec Lua、运行 prefab 工厂或任意回调、批量 SpawnPrefab、探测修改世界。脚本身份声明与名称通过词法分析提取；共享工厂/条件/特殊交互摘录是 candidate，不直接作为百科答案。动态身份和外部机制须集中人工审查。

收集包解压后运行：

```powershell
python developer_tools/import_dst_knowledge.py --source "输入/scripts.zip" --version-file "输入/version.txt" --localization "输入/localization/chinese_s.po" --output "knowledge/imported"
```

若中文已经在 scripts.zip 内可省略 --localization。源码是目录时 --source 指向完整 scripts 目录。扫描所有官方 Lua 的 Prefab 声明，不只扫 prefabs 子目录；条件和动态声明仍须复核。可加 --adapters knowledge/reviewed_adapters.json；模板在 knowledge/reviewed_adapters.template.json。

输出 official_knowledge.json、coverage.json，以及 ybf_official_knowledge.lua 身份索引和最多 64 个 ybf_official_detail_XX.lua。将全部生成的 ybf_official_*.lua 放到 my_best_friend/scripts 后重启游戏。索引不加载全部属性/机制；详细分片按实际查询 require，避免庞大单函数常量池，也不把百科全部送给模型。保留 JSON 与哈希用于复现，不要求玩家手工编辑生成 Lua。

完成导入仍需看 coverage.json 的逐对象缺口。官方总数默认 null；只有来源宇宙、所有动态声明和目录逐项人工核验后才可填写 catalog_review。不能为了获得漂亮数字改标志。

## 集中适配格式

顶层 build 必须是 version.txt 同一个数字构建。entries 键为已经核实的 prefab，facet 可用 properties/uses/sources/recipes/mechanisms/behaviors/restrictions/variants。每条包含 field 或 semantic_key、value、version、certainty。只有 verified 可进入当前事实回答；candidate/unknown 留为缺口或开发证据。

official_script 来源要有 path、line、sha256、version、certainty，导入器校验源文件和行号。official_documentation/reviewed_wiki 来源要有 https URL、reviewed_at，以及 implementation_check（完整的当前官方脚本引用对象，不是空泛的“已核对”文本）。事实数值/布尔需提供自然语言 summary 或由属性字段解释；不要放任模型凭空补说明。独立 prefab 自己有身份记录；同 prefab 状态/皮肤放在 variants 的 value 内，使用 kind=state/skin、name 和条件/关系；不要发明新 prefab。

动态工厂身份可在 identity_expansions 中提供 prefab、source（已核验当前脚本出处）、reviewed_reason，未核验循环仍保留在 unresolved。aliases 集中记录，不能作为无条件执行许可。类别需 category_source。适用字段通过 applicable_facets 指明；not_applicable 必须含 reason 与 verified source，不能随意空填。

completeness_review 必須含 version、reviewer、reviewed_at、checked_topics（按 facet 罗列已核验事实的 semantic_key）和 remaining_gaps=[]。所有适用主题与不适用字段都需复核，才能标完整。catalog_review 则独立记录整个官方对象宇宙的 reviewed_prefab_files、prefab_ids、resolved_declarations（path/line/type/review_reason/prefabs）、reviewer、reviewed_at、version、universe_verified，不能拿单对象完整代替整个目录完整。

相同 semantic_key 的官方脚本事实优先可靠网页；同优先级实现冲突时不任选一条，运行时 Facts 与离线审计都标缺口。当前包没有已核验网页百科条目，不能宣称已经结合网页实现完整机制百科。

## 运行时与上下文

APP_VERSION 用于与导入构建精确核对。它未提供或不一致时，静态知识不作为当前确定事实；先确认实际引擎构建输出再适配版本接口，不能自行设置一个猜测值。现场 inventory、剩余次数、食物基础字段/新鲜度、武器/护甲/生命/容器/科技站标准字段仅来自实际实例。食物基础值不等于包含全部新鲜度、角色、记忆、温度、附加回调的最终效果；查询不执行这些回调。补状态和明确食用仍沿用旧执行系统。

每次上下文至多 8 个相关条目、12 个附近来源，knowledge JSON 总上限 9000 字节，整请求沿用 32768 上限；本地查询至多 4 个目标，回复不超过现有短回复预算。查询按问题保留相关 facet，不无差别附所有配方和动作边界。详细候选证据主要留在离线数据，不充当玩家答案。静态条目不携带现场位置；实际附近来源仍来自朋友感知。

## 不含密钥的按需诊断

默认不输出整份知识上下文。后台可使用 `python external/bridge.py --ai --knowledge-debug` 临时启用相关输入和规范化模型查询输出；已配置密钥值、sk-形式与 token/key 字段被遮蔽，不记录提供商原始响应体或授权头。

游戏服务端控制台可以对实际朋友启用：

```lua
for _,e in pairs(Ents) do if e.components and e.components.ybf_friend then require("ybf_knowledge").SetDebug(e,true) end end
```

Knowledge.Trace(friend) 保存最多 20 条当前内存记录：原句、模型规范化查询、名称片段/候选、最终 prefab、身份依据、检索 facts/unknown、知识来源与实际对象字段。SetDebug(friend,false) 清空诊断记录，不清除底层知识。简短 TRACE 写开发日志；完整内存记录可按需用游戏 json.encode 导出，导出前检查用户文本敏感信息。没有将 API 密钥或后台配置 token 注入知识层。控制台命令仅用于调试现有朋友，不调用 prefab 工厂。
