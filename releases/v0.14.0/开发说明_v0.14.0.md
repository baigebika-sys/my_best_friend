# v0.14.0 开发接口与证据边界

新增 `my_best_friend/scripts/ybf_knowledge.lua`，供任务、感知、配方、聊天共用。身份来自加载注册表、配方与实际观察；类别无法可靠确定时仍为 unknown。对象实例属性只从实际库存/附近对象读取。来源记忆最多256种产物，每种最多4条关系，只表示实际观察过的来源类型，不存全图坐标。位置只存在当次实际附近来源片段中；未新增玩家线索记忆和远程找物。

## 查询接口

- `Catalog(inst)`：当前可靠身份集合，不发送全表给模型。
- `Names(inst,name)`：名称/别名对应的全部候选；`Resolve(inst,name,current_text)`：唯一结果或 name_unknown/name_ambiguous。执行始终以可靠 prefab 为标识。`CandidateText` 只缩短显示，不缩短真实消歧判定。
- `Entry(inst,prefab)`：身份、属性事实 facts、规则推导 derived、未知 unknown、recipes、sources 与 capability。
- `Recipes(inst,prefab)`：当前配方事实，动态产出回调不执行，特殊条件标未知；此接口不会制作。
- `Sources(inst,entity)`：实际组件能够说明的产物、动作、工具、许可、可用性及证据。不调用 GenerateLoot/lootsetupfn。
- `CanAcquire(inst,prefab)` / `Capability(inst,prefab)`：是否已有支持的获取规则，以及名称/来源/制作能力缺口；六种原基础资源保留经过验证的兼容能力。
- `Context(inst,current_text,nearby_entities)`：相关条目和实际附近来源。
- `Answer(inst,name,properties|recipe|sources,current_text)`：本地有依据的只读自然语言说明。

任务的 RequestIntent、PauseTask、ResumeTask、ModifyTask、Cancel、ProgressText 接口和含义保留。materials/craft 模式的可执行配方仍须通过原 PlanRecipe/Check/Perform；扩大配方知识并没有扩大特殊制作执行权。

## 模型包上限

知识片段最多8物品、12附近来源、每物品4配方及每配方12普通材料；知识 JSON 上限9000字节。请求正文达到31000字节会依次裁剪可选知识、补给、附近与库存片段，保留当前输入和权威任务事实；硬上限32768。裁剪标记明确告知上下文不完整，模型不得把未列出视作不存在。玩家回复控制在600字节内。重名候选只显示前4个，绝不会因为显示上限自动选中第一个。

只读知识协议：`intent=query_knowledge, action=knowledge, item={name="原名称或可靠prefab",kind="properties"|"recipe"|"sources"}, quantity=null`，不接受目标执行字段。普通名称/错别字仍由模型理解，本地不添加每种命令关键词执行器。多种物品目标仍是同一任务，非多任务队列。

## 开发诊断

名称未识别 name_unknown、重名 name_ambiguous、来源不支持 source_unsupported、来源未知 source_unknown 分开。已知普通来源当前不成熟/不在附近表现为受阻、没有可获取目标，背包/角色/工具等条件保持原分类。执行失败沿用有限失败和安全异常保护。知识日志带 query/item/capability，工作受阻日志带 category/task/step；玩家收到自然说明。

## 复现

在完整包根目录运行，Python3标准库及 `liblua5.4.so.0` 可用：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 developer_tools/run_knowledge_checks.py
PYTHONDONTWRITEBYTECODE=1 python3 developer_tools/run_language_checks.py
PYTHONDONTWRITEBYTECODE=1 python3 developer_tools/run_foundation_checks.py
PYTHONDONTWRITEBYTECODE=1 python3 developer_tools/run_lua_checks.py
PYTHONPATH="$PWD/external" python3 -m unittest discover -s tests -p test_knowledge_schema.py
```

同样的 unittest 命令分别使用 test_language_schema.py、test_goal_ai.py、test_chat_ai.py、test_bridge.py、test_config.py，即本阶段33项。不要把保留的旧直接动作测试当作当前生产协议。

参考组件来自公开 DST 脚本镜像，不证明用户安装版本一致。下载路径、日期、SHA-256 见 `tests/reference/v0140_source_manifest.json`；未修改的 Pickable 组件在 pickable_v0140.lua。模拟只调用实际 PICK/Pickable 代码，在正常动作执行时允许模拟 SpawnPrefab 产出；知识读取时则测试禁止 SpawnPrefab、掉落设置回调和动态配方回调。花朵字段依据 flower.lua 的 SetUp("petals",10)、remove_when_picked，以及 thorny 标签核对。未在云端执行完整花朵工厂或 DST 引擎。

测试夹具修正：原树木夹具曾复用矿石掉落元数据，现改为与其真实模拟产出一致的 log；原“已有库存不应发生任何扫描”改为验证无新采集且库存保留（新增知识感知为只读）；异常文本断言改为既有生产自然反馈。没有删除数量、消耗、旧回调或交付断言。
