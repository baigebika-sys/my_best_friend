# v0.14.0：运行时知识与通用普通采集

基线为用户明确确认已测试通过的 v0.13.0。本版不改变任务控制含义，不增加主动工作、队列或跨存档任务恢复。

## 原限制与改动

- `external/decision.py` 的旧资源/配方名单只保留给兼容解析；生产模型仍禁止旧直接资源动作。新增只读 `query_knowledge/knowledge` 协议。
- 旧提示词主要列举六种基础资源，现在使用当前相关知识与实际附近来源；模型不能把知道名字或配方视为执行许可。
- `ybf_task_intent.lua` 不再以六种资源名单决定全部获取能力，接入可靠身份与统一能力查询；未知、重名和不支持分开反馈。
- `ybf_work_resources.lua` 不再为草/树枝写植物分支，统一读取来源关系；普通采摘用原版 PICK，拾取用原版 PICKUP，砍挖仍用原版 CHOP/MINE。
- `ybf_work_crafting.lua` 的可执行配方名单集中到知识层，仍保留斧头、鹤嘴锄、石砖、木板、绳子、火把；原执行前条件检查、实际消耗/产出审核保留。
- 知识查询从本地真实数据回答；查询不修改任务，也不取消待解析工作请求。补状态、有限重试、任务起点约束、精确交付仍沿用原实现。
- 启动 READY 横幅遗留 0.9.6 文字已修为 0.14.0。

## 三项范围说明

**可以通用读取的信息**：已加载 Prefabs 的可靠当前语言名称、实际观察对象的显示名称、常见别名；实际对象中食物效果估算、工具动作、装备槽和耐久；AllRecipes 中普通材料、数值产出、科技及当前角色学习状态。记录直接组件/配方事实、规则推导与未知；不批量生成 prefab，不运行 prefab 工厂、动态掉落生成或配方产出回调来读取知识。完整用途、自定义效果、动态产出、特殊材料/设施/额外制作条件可能未知。基础材料数量与角色材料倍率分别记录，执行器仍按实际配方核验。

**已经通用支持的动作**：朋友实际附近的普通地面物品拾取；可靠 `pickable.product`、可交互且未卡住的普通采摘对象，花瓣和浆果无需各自独立任务分支，标准第三方 pickable 也可复用。静态可靠掉落、普通安全树木/矿源的 CHOP/MINE 可建立产物关系并复用工具准备。概率掉落只是可能来源，只有实际入包才算进度；不会用工作回调冒充数量。允许原版采摘按其正常事件移除花朵，不是额外拆除动作。

**仍需适配的特殊对象**：动态/多产物回调、searchable、特殊工具或机制、带刺玫瑰、危险对象、活体/战斗目标、建筑/容器、特殊加工设施和建筑放置。挖植物、敲建筑、攻击、点火没有新增许可。普通花朵的 petals 与其他产物按实际组件区分；不会把恶魔花瓣当花瓣。特殊模组只有标准组件形式可尽量兼容，不保证所有自定义机制可理解或安全执行。

## 最少游戏测试：五组

所有指令都从真实朋友聊天入口发送；不要用控制台直接调用工作接口替代语言验收。只针对本版变化测试。

1. **普通花朵 → 花瓣 → 交付**：朋友先无花瓣，身边32单位内有至少2朵可采普通花，避开带刺玫瑰。发“帮我采集2个花瓣给我”。应采花、实际拾得花瓣并真实交付2个。朋友和玩家数量、花朵消失应一致；不能误采恶魔花朵当花瓣。如当前角色有采摘效果限制，仍应遵循原版。
2. **另一种普通对象**：朋友无浆果，附近有2个成熟普通浆果丛，发“帮我采集2个浆果给我”。应复用普通采摘并真实交付；没有成熟来源时如实报告，不能把未采到的东西算完成。
3. **有依据且只读的查询**：给朋友一份浆果及斧头，问“浆果有什么效果”“斧头能做什么”“石砖怎么制作”。食物依据当前实例/朋友吸收效果估算；工具应说明砍伐；原版石砖配方应来自实际配方表（默认3石头→1石砖及科学条件）。若其他模组改变配方，以实际表为准。再在工作期间查询一次，任务与进度不能重置；没有观察到食物属性时应说明未知而不编数字。
4. **认识但不支持、重名**：问“科学机器怎么制作”，可读到配方但应说明制作执行器不支持；再说“给我制作1个科学机器”，不得放置建筑或消耗材料。若使用有同名物品的模组，发含糊名称请求，应先询问具体对象，不随意选 prefab。
5. **必要回归与取消**：采1个树枝并交付一次；再开始尚未完成的花瓣/浆果任务，说“取消这个任务”。不再执行旧采摘、旧回复或交付，已得物资保留，原跟随/等待安排保留。取消指令可能需要模型往返；紧急停止仍可用原“停止任务”直达本地。
