# v0.16.0-r5：移除人为玩家占位限制

基线为 0.16.0-r4，游戏参考源码构建 756039。保留 r4 的服务器沙箱 RPC 修复、点选回执与无需二次确认流程。

## 改动与原因

此前模组通过 PlayerAt / WaitForPlayer 在原版放置检查之外，额外阻止玩家站在施工点时施工，并进入等待及超时状态。这是本次已确认的规则错误；不能据此认定所有停滞都由它造成。

删除这两个函数及调用、等待/超时流程、动作等待标记和“请离开施工点”等提示。点选成功直接恢复任务；玩家脚下定位保存坐标后直接准备材料并施工。任务循环清退旧 waiting_player / player_wait_timeout 阻塞及 pending_build_wait / wait_started 残留，不自动恢复手动暂停，不修改已选坐标或预制状态。

保留当前游戏原版 CanDeployRecipeAtPoint / builder 放置检查与真实材料消耗、预制及实体核实。不会为了让任务完成绕过地形、建筑或其他实际障碍判定。

## 其他停滞的诊断

检查了工作循环、缓冲动作及朋友状态图的占用接口。未凭现有资料定位所有“抽动一下就停止”的原因，因此不宣称全部解决，也不强行清除有效动作。建筑任务没有自身在途动作、却被 ActionBusy 连续阻塞超过 3 秒时，输出限频的 [YBF BUILD FLOW] 日志，包含任务、步骤、buffered_action / self_maintenance / stategraph 原因、动作及状态名称；同类日志最多每 10 秒一次，不记录密钥。等待问题再次发生时，这些记录可区分实际阻塞来源。

## 验证与边界

本地建筑集成模拟、真实自然语言入口的模拟提供器回归、Lua 工作回归、通信基础回归及 76 项 Python 测试通过。模拟包括玩家始终站在固定点与玩家坐标原点、材料准备、原版预制函数、实际放置函数及实体核实；另有友谊仓库取原木并递归制作木板后施工。旧玩家等待状态清退、手动暂停保留、原版障碍拒绝及 r4 服务器沙箱 RPC 回归通过。

使用提供的原版函数，世界、路径、状态图依赖和网络仍是模拟。未进行真实模型调用或 DST 游戏实测；不能将上述通过视为游戏施工已验证。

## 最少游戏验收

1. 同步替换客户端与服务器模组，替换并重启 external 后端；保留原密钥配置。
2. 请求“造一个木牌”，点击合法位置后保持玩家站在该点：应直接确认位置、取材/预制并放置，不提示让开，也不用再次确认。
3. 请求“在我脚下造一个木牌”，保持站位。仅按原版规则检查，不进入玩家等待。
4. 用友谊箱提供原木，重复测试递归木板制作；再选建筑或地形确实不合法的位置，检查仍正确拒绝。
5. 必要回归暂停、恢复、取消；发生停滞时保留完整服务器日志中的 [YBF POINT]、[YBF BUILD]、[YBF BUILD FLOW]，检查动作、状态及具体拒绝原因。
