# v0.15.0-r1 友谊小花赋予操作修复

## 原因与改动

原版鼠标手持物品悬浮时，左键收集 GetUseItemActions(..., nil/false)，右键收集 GetUseItemActions(..., true)。0.15.0把赋予注册限制为right=true，因此正常左键显示仍只有“存放”。赋予动作默认priority=0，与原版STORE相同，即使右键收集到也没有可靠保证排在前面。截图可以确认左侧仍显示存放，但没有实际日志不能断定其每次右键的排序结果。

本次赋予参考官方升级道具的普通USEITEM流程，允许左右键悬浮产生动作，priority=2高于STORE默认0。解除只在右键场景操作产生，同样优先于RUMMAGE。增加空目标保护，排除烧毁箱的赋予入口；支持范围与服务器距离、花归属验证保留，操作不消耗花，不替换实体或改变内容物。

另一个已核实问题：官方AddComponentAction会覆盖同一mod/type/component已有回调。旧modmain对USEITEM/inventoryitem注册了两次，新赋予回调覆盖了原有朋友喂食／死亡目标送物保护。合并为单一注册，保留旧过滤后再收集新操作。

本次没有改变任务、材料、制作、知识或自我维持逻辑；普通未授权箱仍禁止朋友自动存取。后台health为version=0.15.0、revision=r1；modinfo版本为0.15.0-r1。

## 验证边界

新回归抽取用户已提供的DST构建756039 componentactions.lua和components/playeractionpicker.lua原函数：原版注册／收集、库存STORE与场景RUMMAGE收集、优先级排序和GetUseItemActions/GetSceneActions。使用模拟实体，不启动游戏，不探测或修改世界。

同一回归在修改前失败，原因为“left hover must select friendship grant instead of STORE”；修改后通过。覆盖左右键赋予优先、四类容器、仅客户端副本数据时的显示候选、右键解除、原存放／开箱保留、小花不消耗、重复不叠加、原喂食与死亡目标过滤、空目标。既有服务器拒绝他人花／超距离、客户端netvar名称测试也通过。原仓库／配方／多目标模拟、自然入口7句、基础工作与现行Python71项回归通过。证据在tests/v0150_r1_*.log，引用及哈希在tests/v0150_r1_action_sources.json。

这不是真实DST网络同步、动作动画或实际鼠标交互实测；真实模型也未调用。

## 安装与最少验收

1. 完全退出游戏并停止服务器；备份旧模组与密钥，替换my_best_friend模组目录后重新启动。多人服务器和客户端均更新此修复；旧已加载会话不会自动刷新动作注册。完整包的external只是revision标识更新，可一并替换并保留自己的api_key.txt。
2. 从背包拿起友谊小花使其跟随鼠标，不是装备。悬浮普通箱：应显示“赋予友谊”，点击左键或右键，靠近后名称变为“友谊＋原名称”；花仍在手中、箱内物品不变。
3. 收起小花，右键已授权箱应显示“解除友谊”；点击后恢复名称。左键正常开箱应仍可使用。重复赋予不重复加前缀。
4. 对龙鳞箱、冰箱、盐盒各试一次。成功后再继续0.15.0原有任务与保存／重载／升级验收步骤；此次修复没有替代那些游戏验收。
